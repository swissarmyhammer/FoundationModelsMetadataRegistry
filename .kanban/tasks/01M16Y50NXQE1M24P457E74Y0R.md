## What

FoundationModelsRanker is removing its own Router dependency on branch `main`. Its public API changes in three ways that this package must follow:

1. `SelectionConfig.model` changes from `@Sendable (String, Grammar) -> any AgentSession` to `@Sendable (String) -> any AgentSession`. The grammar argument is gone.
2. `SelectionTier.idEnumGrammar(ids:) -> Grammar` becomes `SelectionTier.idEnumSchema(ids:) -> String`, which returns JSON Schema source text.
3. `RoutedEmbedderAdapter` and `RoutedAgentSession` are deleted. `TextEmbedding` and `AgentSession` stay public and unchanged.

Ranker also adds `Searcher.init(_ items:, embedder:, session: any AgentSession, ...)`. The existing factory-form `init` keeps its signature, so `MetadataSearcher` does not have to change.

### What `idEnumSchema(ids:)` returns

It returns the WHOLE response schema, not the per-element enum. It starts from `Selection.generationSchema` (the `@Generable` type is `Selection { ids: [String] }`), makes three injections, and re-encodes:

```json
{
  "type": "object",
  "properties": {
    "ids": {
      "type": "array",
      "items": { "type": "string", "enum": ["alpha", "bravo"] },
      "uniqueItems": true,
      "maxItems": 2
    }
  }
}
```

The `enum` sits at `properties.ids.items.enum`. `uniqueItems` and `maxItems` sit one level up at `properties.ids`. `maxItems` equals `ids.count` exactly. An empty `ids` array gives an empty `enum` and `maxItems: 0`; that is intended.

`maxItems` is load-bearing, not decoration. The xgrammar pipeline enforces `minItems`/`maxItems` but silently ignores `uniqueItems`. Without the cap, a compiled grammar permits an unbounded array of repeated enum members. Ranker observed a roughly 6150-token runaway on an off-topic intent. Keep the cap if this schema is ever compiled into a grammar.
