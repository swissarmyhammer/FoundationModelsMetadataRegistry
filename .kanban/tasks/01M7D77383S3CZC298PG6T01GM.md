## What

Add the code that runs each tier configuration over `BenchmarkCatalog` and `BenchmarkIntents`, and writes one `BenchmarkReport`.

Files:
- `Benchmarks/Package.swift`: add the packages FoundationModelsExtras and FoundationModelsDecision, with the same SSH URLs and `branch: "main"` as the root manifest. The `RankingBenchmark` executable target links these products: `FoundationModelsExtras` (core: `PooledEmbedder`, `PooledModel`, `ModelPool`, `HubModelLoader`), `FoundationModelsExtrasLlamaCpp` (`LlamaCppModelLoader`, for the GGUF configuration) and `FoundationModelsDecisionPooled` (`PooledDecisionModel`). `BenchmarkSupport` links none of them, so that its unit tests build no model runtime. Add executable target `RankingBenchmark`.
- `Benchmarks/Sources/BenchmarkSupport/BenchmarkConfiguration.swift`: `struct BenchmarkConfiguration { let name: String; let makeSearcher: @Sendable ([BenchmarkItem]) -> MetadataSearcher<BenchmarkItem> }`. All configurations use the same `limit` (5) and the same intents. Also hold the list of the six configuration names here (`BenchmarkConfiguration.allNames`), so that tests can read it.
- `Benchmarks/Sources/BenchmarkSupport/BenchmarkRunner.swift`: `static func run(_ configurations: [BenchmarkConfiguration], intents: [LabeledIntent], catalog: [BenchmarkItem], repeats: Int) async -> BenchmarkReport`. For each configuration: build one searcher, do one warm-up search and record its duration apart (it loads the models and embeds the catalog), then search each intent `repeats` times and record the ranked ids and the duration of each search. An error of one search counts as an empty result and as one error in the report; the run continues.
- `Benchmarks/Sources/RankingBenchmark/main.swift`: arguments `--output <dir>` (required), `--configurations <name,...>` (default: all), `--repeats <n>` (default 3). Writes `report.json` and `report.md` to the output folder, and prints the markdown table.
- `Benchmarks/Sources/RankingBenchmark/Configurations.swift`: the real configurations. Each one except `retrieval-keyword` uses the embedder `PooledEmbedder(ref: "mlx-community/Qwen3-Embedding-0.6B-4bit-DWQ")`, so the candidates of the decision tier are the same as the retrieval results:
  - `retrieval-keyword`: no embedder, `.retrieval`.
  - `retrieval-semantic`: `.retrieval`.
  - `selection-qwen3-4b`: `.selection`, `SelectionConfig(model: PooledModel(ref: "mlx-community/Qwen3-4B-4bit"), preamble: .librarianDefault)`.
  - `selection-apple`: `.selection` with `SystemLanguageModel.default`. When the model is not available, the report row gives the reason and no metrics.
  - `decision-qwen3-4b`: `.decision`, `DecisionConfig(model: PooledDecisionModel(ref: "mlx-community/Qwen3-4B-4bit"))` (the default `GenericPromptFormat`). The same weights as `selection-qwen3-4b`, so this row compares the method only.
  - `decision-decider-4b`: `.decision`, `DecisionConfig(model: PooledDecisionModel(ref: "Mapika/decider-4b-GGUF/decider-4b-v3-Q4_K_M.gguf", pool: ggufPool, format: DeciderPromptFormat()))`. The ref names the GGUF file (this is the form in FoundationModelsDecision `plan.md`). `ggufPool` is a `ModelPool` with `HubModelLoader(gguf: LlamaCppModelLoader())`.

## Acceptance Criteria
- [ ] `swift build --package-path Benchmarks` passes.
- [ ] `BenchmarkRunner.run` gives one report row for each configuration, with the metrics of each intent kind, p50, p95, the warm-up duration and the error count.
- [ ] An error in one search does not stop the run.
- [ ] `RankingBenchmark --output <dir>` writes `report.json` and `report.md` to `<dir>`.
- [ ] The `BenchmarkSupport` target links no model runtime product.
